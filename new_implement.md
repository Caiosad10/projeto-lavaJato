# Ideias novas

1. Token pra confirmar chegada/agendamento do cliente -> - (QR code em totem pra confirmar chegada no local)
2. Taxa de cancelamento se usuário quiser cancelar perto do horario agendado
3. Melhorar o UI/UX com cores

1 -> Imaginando uma operação real, tem pessoas que agendam determinado serviço e não vão, "roubando" vaga de quem poderia realmente estar lá. Vamos supor que uma pessoa agendou 2 serviços (um de 1h e outro de 30min, ela agendou no horario das 10hrs, então o estabelecimento só terá o proximo horario disponivel as 11:30), imagine que esse cliente não foi, então ele estará ocupando dos horarios possiveis (10:30, 11hrs). O token para confirmar vem justamente para validar a presença do cliente no local. 

Fluxo imaginado: Cliente agenda serviço na aplicação web -> Chega no local -> (Aqui vou imaginar um totem com uma tela que terá um QR code, mas precisamos adaptar para a apresentação para a professora - Uma tela especifica com qr code, que assim que passamos a camera, ela interliga ao sistema e confirma (API)) Vai a um totem ou a recepção, lê o qr code com o celular, confirma e o sistema registra -> Se por algum acaso, dentro de 15mins de tolerancia após o horario, não houver validação desse codigo, o serviço é cancelado, o cliente que agendou é informado sobre o cancelamento, e os horarios que estavam ocupados, agora passam a estar disponiveis

2 -> Uma situação que o cliente tenha agendado um serviço para amanhã, mas ele depois descobre que infelizmente não vai poder ir. Ele pode cancelar, recebe seu estorno, mas só se tiver dentro do tempo limite: O cliente pode cancelar o serviço, no maximo, faltando 1hr antes do agendamento (Se eu agendei as 10hrs, eu posso cancelar ate as 9hrs). Mas temos que ter uma certa tolerancia a agendamentos recentes, por exemplo: São 9:15/9:30, estava querendo lavar meu carro, entro na aplicação, vejo um estabelecimento perto de casa, e tem o horario as 10hrs. Agendo esse horario, não levo mais que 5mins, mas poxa vida, do nada aconteceu alguma coisa, vou ter que cancelar. Nessa situação é toleravel!

Cancelamentos até no maximo uma hora antes vem para aqueles casos de eu, hoje, agendar para dias posteriores. A taxa de cancelamento vem para aquele cliente que deseja cancelar o agendamento após essa 1hr antes (marquei as 10hrs, mas vim querer cancelar as 9:15/9:30, faltando menos de uma hora para o agendamento), e então, se o cliente realmente quiser cancelar, ele pode mas agora irá pagar uma taxa, então, ele receberá o estorno de uma parte do valor pago. Vamos supor que o cliente agendou um serviço de R$80 - a taxa será em porcentagem - mas vamos supor que nesse caso, a taxa seja R$ 5,50, então o cliente receberá o estorno parcial, onde dos R$ 80 pagos, será devolvido $74,50. 

Precisamos ser mais amigo do cliente tambem, sabemos que isso pode ser visto de forma negativa pelo cliente, então, nessa situação especifica (o cliente quer cancelar faltando menos de uma hora do agendamento, ele não agendou recente, ele não quer pagar taxa), ele pode reagendar - mas aqui tem que ter uma proteção, vou mostrar no fluxo: Agendei há um tempo o serviço -> falta menos de uma hora do agendamento -> quero cancelar -> sou informado da taxa mas não é que eu queira cancelar, eu até iria mas aconteceu alguma coisa, não quero pagar a taxa pois eu quero reagendar -> Inves de seguir com o cancelamento, eu reagendo e me organizo para ir no novo dia e horario. Esse é o fluxo ideal, mas a gente sabe que o ser humano é pilantra, então precisamos de proteção: Não da para cancelar o reagendamento, aqui ele não paga taxa, pois se ele não for, não ha estorno, cancelamento, ele simplemente não vai e perde o dinheiro por tentar ser pilantra

Resumindo o 2º, Taxa de cancelamento é aplicado faltando menos de 1hr do agendamento, exceto se o agendamento é recente (feito faltando menos de uma hora do agendamento). A taxa é por porcentagem (preciso estipular para que o valor não seja alto, e sim um valor simbolico para o cancelamento). Se o cliente não quer cancelar por mal e quer reagendar, ele pode, mas ele não irá poder cancelar o reagendamento

3 -> Uma melhora em cores para interface, des da parte do wizard, nas barras de progresso dentro de Agendamentos, e tambem nas notificações, tanto nos alertas (popup) quanto no modal de "notificações"
